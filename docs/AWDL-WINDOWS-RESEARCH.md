# Native Windows AWDL integration

Research date: 2026-10-10. Inspected OWL fork: `jedbillyb/owl` at `832d70f815c3d4a06a02117bf0fc5e868daa1ff0`; Devourer: `OpenIPC/devourer` at `f369aac553c9ce884901115ef9e66509f93c5683`. Target: RTL8852CE PCIe with Windows remaining running. This document describes an implementation path; no native AWDL/iPhone transfer has been demonstrated on this PC.

## Recommended permanent boundary

Use three independently built components: Windrop's existing application/protocol process; a GPL-3.0-or-later OWL Windows process providing an IPv6 interface; and a Devourer-derived radio process using the native device driver. The radio process should expose a documented, client-independent raw-frame and channel API. Keep OWL and Devourer source, binaries, builds and licenses separate. This is a proposed design, not an existing upstream Windows implementation.

```text
Windrop UDP/mDNS and HTTPS/TCP sockets
              |
       scoped Windows IPv6 interface
              |
    signed Wintun DLL + OWL Windows process
              |
    generic raw-frame/channel IPC
              |
    Devourer radio process + Windows PCIe driver
              |
         RTL8852CE / iPhone AWDL
```

OWL already separates `src/` into `libawdl`, containing election, peer state, synchronization, channel sequence, scheduling and frame parsing/serialization. Its daemon adds pcap, libev, Linux libnl and TAP integration. Reuse the protocol library and preserve daemon scheduling behavior in a Windows host adapter; replacing socket names or compiling the current daemon unchanged does not supply Windows radio access. [Protocol build](https://github.com/jedbillyb/owl/blob/832d70f815c3d4a06a02117bf0fc5e868daa1ff0/src/CMakeLists.txt), [daemon dependencies](https://github.com/jedbillyb/owl/blob/832d70f815c3d4a06a02117bf0fc5e868daa1ff0/daemon/CMakeLists.txt).

## Radio contract

Devourer's `ITransport` separates register access, frame submission, receive delivery and lifecycle. The current PCIe transport is VFIO-specific; `PcieDmaAx` already contains the RTL8852CE ring algorithm. A native Windows implementation must replace exclusive device acquisition, BAR/config access and DMA allocation/mapping rather than simulate VFIO with an IP tunnel. `WiFiDriver::CreateRadioPcie` currently specifically accepts `PcieTransport`, so adopting another implementation of `ITransport` also requires refactoring that factory's PCI identity dispatch. [Transport interface](https://github.com/OpenIPC/devourer/blob/f369aac553c9ce884901115ef9e66509f93c5683/src/Transport.h), [PCIe transport](https://github.com/OpenIPC/devourer/blob/f369aac553c9ce884901115ef9e66509f93c5683/src/PcieTransport.h), [factory](https://github.com/OpenIPC/devourer/blob/f369aac553c9ce884901115ef9e66509f93c5683/src/WiFiDriver.h#L44), [AX DMA](https://github.com/OpenIPC/devourer/blob/f369aac553c9ce884901115ef9e66509f93c5683/src/PcieDmaAx.cpp).

The worker can use `InitWrite`, then run `StartRxLoop` on its receive thread while the control thread serializes `SetMonitorChannel`/`FastRetune` and TX. `send_packet` takes radiotap plus an 802.11 MPDU, matching OWL's full-frame serializers. RX returns `Packet.Data`, a borrowed span containing the bare MPDU; copy it before the callback returns. Forward timestamps, channel, measured signal and CRC/FCS state as scalar metadata rather than sharing Devourer or OWL internal structures across processes. [Radio lifecycle and threading](https://github.com/OpenIPC/devourer/blob/f369aac553c9ce884901115ef9e66509f93c5683/src/IRadio.h#L30), [received packet representation](https://github.com/OpenIPC/devourer/blob/f369aac553c9ce884901115ef9e66509f93c5683/src/RxPacket.h#L109), [OWL serializers](https://github.com/jedbillyb/owl/blob/832d70f815c3d4a06a02117bf0fc5e868daa1ff0/src/tx.c#L362).

OWL `awdl_rx` requires radiotap followed by the MPDU. Add a radiotap header containing FLAGS and DBM_ANTSIGNAL, setting FCS/BADFCS consistently with Devourer metadata, and remove the FCS exactly once. Realtek's RX representation includes FCS. Do not pass the bare MPDU or fabricate only an empty radiotap header: this OWL revision leaves local `flags` and `rssi` uninitialized if those fields are absent. Initializing parser defaults is a necessary correctness fix when metadata can be missing; unknown signal must remain distinguishable from a measured value. [OWL RX and metadata parser](https://github.com/jedbillyb/owl/blob/832d70f815c3d4a06a02117bf0fc5e868daa1ff0/src/rx.c#L436), [Devourer FCS contract](https://github.com/OpenIPC/devourer/blob/f369aac553c9ce884901115ef9e66509f93c5683/src/RxPacket.h#L109).

The AX transport requires device-visible addresses below 4 GiB. Windows should obtain DMA logical addresses from framework common buffers and reject ranges exceeding descriptor width; a userspace pointer or assumed physical address is not equivalent. KMDF documents alignment before `WdfDmaEnablerCreate`, and `WdfCommonBufferGetAlignedLogicalAddress` returns the mapped address used by the device. Driver ownership and power/removal paths must quiesce hardware before releasing rings. [Existing address constraint](https://github.com/OpenIPC/devourer/blob/f369aac553c9ce884901115ef9e66509f93c5683/src/PcieTransport.h#L25), [KMDF DMA enablement](https://learn.microsoft.com/en-us/windows-hardware/drivers/wdf/enabling-dma-transactions), [DMA logical addresses](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/wdfcommonbuffer/nf-wdfcommonbuffer-wdfcommonbuffergetalignedlogicaladdress).

## Scheduling and Windows portability

Keep AWDL state mutation on one event-loop thread. Receive workers enqueue copied packets; driver/channel completions wake the loop. Preserve these operations rather than substituting a periodic broadcast loop:

| Operation | Existing behavior to retain |
| --- | --- |
| Incoming frame | `awdl_rx`, peer callbacks and decoded data delivery |
| PSF | Periodic action frame, initial 110 TU (112.64 ms) |
| MIF | Nonzero channel only, rearmed to the middle of the next extended availability window |
| Channel | Index the 16-slot sequence using synchronized EAW phase; rearm at the next boundary |
| Unicast | Look up the destination peer; use `awdl_can_send_unicast_in` and 3 TU guard |
| Multicast | Use `awdl_is_multicast_eaw`, slots 0/10, and 16 TU guard |
| Peer expiry | Remove old peers, rerun election, adopt the elected master's channel sequence |

These behaviors are implemented in the daemon, not all in `libawdl`. Initial EAW length is 16 TU times presence mode 4, or 65.536 ms. Channel changes were deliberately made asynchronous after blocking switches averaged 8.5 ms on the author's hardware. A Windows port should report actual completion/failure and channel state, and measure requested versus executed channel/TX deadlines. [Initialization](https://github.com/jedbillyb/owl/blob/832d70f815c3d4a06a02117bf0fc5e868daa1ff0/src/state.c#L26), [sync time](https://github.com/jedbillyb/owl/blob/832d70f815c3d4a06a02117bf0fc5e868daa1ff0/src/sync.c#L23), [TX scheduling](https://github.com/jedbillyb/owl/blob/832d70f815c3d4a06a02117bf0fc5e868daa1ff0/daemon/core.c#L178), [channel switching](https://github.com/jedbillyb/owl/blob/832d70f815c3d4a06a02117bf0fc5e868daa1ff0/daemon/core.c#L286), [expiry and timer registration](https://github.com/jedbillyb/owl/blob/832d70f815c3d4a06a02117bf0fc5e868daa1ff0/daemon/core.c#L558), [guards](https://github.com/jedbillyb/owl/blob/832d70f815c3d4a06a02117bf0fc5e868daa1ff0/src/schedule.h#L28).

Replace `clock_gettime(CLOCK_MONOTONIC)` with a cached-frequency `QueryPerformanceCounter` conversion to microseconds. Use an unnamed high-resolution waitable timer for the nearest protocol deadline, with a relative one-shot due time, alongside stop, RX and I/O completion events. Windows supports `CREATE_WAITABLE_TIMER_HIGH_RESOLUTION` from Windows 10 1803; timer due times use 100 ns units, but neither this API nor a precise timestamp establishes bounded radio latency. Recompute scheduling after waking and resynchronize after suspend/resume. [OWL clock](https://github.com/jedbillyb/owl/blob/832d70f815c3d4a06a02117bf0fc5e868daa1ff0/src/state.c#L103), [QPC guidance](https://learn.microsoft.com/en-us/windows/win32/sysinfo/acquiring-high-resolution-time-stamps), [high-resolution timer](https://learn.microsoft.com/en-us/windows/win32/api/synchapi/nf-synchapi-createwaitabletimerexw), [relative due times](https://learn.microsoft.com/en-us/windows/win32/api/synchapi/nf-synchapi-setwaitabletimerex).

Use C compilation with `/std:c11` or `/std:c17`; the source contains C compound literals and designated initializers. Do not change all compilation to C++ to solve a header error. Build only the protocol library and radiotap parser, not the original daemon or radiotap's POSIX `parse.c` executable. [MSVC C standards](https://learn.microsoft.com/en-us/cpp/build/reference/std-specify-language-standard-version?view=msvc-170), [OWL build](https://github.com/jedbillyb/owl/blob/832d70f815c3d4a06a02117bf0fc5e868daa1ff0/src/CMakeLists.txt).

| Source barrier | Windows adaptation |
| --- | --- |
| `wire.h`, `peers.h`: `net/ethernet.h`; `channel.h`, `ieee80211.h`: `netinet/ether.h` | Shared compatibility definition of the six-byte `ether_addr`, Ethernet lengths/constants and MAC formatter |
| `wire.h`: `endian.h` | Define 16/32/64-bit host/little/big conversion functions; avoid multiple evaluation |
| `rx.c`: `netinet/in.h`, `netinet/ip6.h` | Replace/remove unavailable headers; this revision does not use a POSIX IPv6 structure in the parser body |
| `frame.h`, `ieee80211.h`: GNU packed attributes | Scoped `#pragma pack(push, 1)`/`pop` around actual wire declarations, preserving normal packing elsewhere |
| `rx.c`, `tx.c`: GNU unused attributes | Conditional annotation or explicit unused parameter handling |
| `state.c`: POSIX monotonic clock | QPC implementation described above |
| `log.c`: `localtime_r(&t, &lt)` | Windows `localtime_s(&lt, &t)` and check its error result |
| radiotap `platform.h`: GNU statement expression, `typeof`, packed dereference, `endian.h` | Fixed-width `memcpy` unaligned readers and explicit endian conversion |
| radiotap `radiotap.c`: pointer casts to `unsigned long` | Use `uintptr_t` or pointer differences for bounds/alignment arithmetic; Windows x64 pointers are 64 bits while `long` stays 32 bits |

Preserve wire layout with compile-time size checks, including radiotap base 8 bytes, 802.11 base header 24, LLC header 8, AWDL action base 16 and data header 8. Keep existing wire tests. Radiotap is pinned to `94984dd829a605a2d7af55241145c159607f3b30`; its parser offers the ISC license alternative, which is compatible with the OWL process. [OWL wire/endian definitions](https://github.com/jedbillyb/owl/blob/832d70f815c3d4a06a02117bf0fc5e868daa1ff0/src/wire.h#L23), [packed definitions](https://github.com/jedbillyb/owl/blob/832d70f815c3d4a06a02117bf0fc5e868daa1ff0/src/frame.h), [radiotap platform macros](https://github.com/radiotap/radiotap-library/blob/94984dd829a605a2d7af55241145c159607f3b30/platform.h), [radiotap pointer arithmetic/license](https://github.com/radiotap/radiotap-library/blob/94984dd829a605a2d7af55241145c159607f3b30/radiotap.c#L126), [MSVC packing](https://learn.microsoft.com/en-us/cpp/preprocessor/pack?view=msvc-170), [Windows data model](https://learn.microsoft.com/en-us/windows/win32/winprog64/abstract-data-models), [Windows localtime](https://learn.microsoft.com/en-us/cpp/c-runtime-library/reference/localtime-s-localtime32-s-localtime64-s?view=msvc-170).

## Wintun host-side ABI

Wintun is a signed virtual **layer-3 IP** adapter, not a Wi-Fi driver. Dynamically resolve its WINAPI functions: create/open adapter, get LUID, start session; receive/release packets; allocate/send packets; get read-wait event; end session and close adapter. Ring capacity is a power of two between 128 KiB and 64 MiB. On `ERROR_NO_MORE_ITEMS`, wait on the session event; do not close that owned event. On send-ring overflow, apply bounded backpressure. [Official ABI](https://git.zx2c4.com/wintun/tree/api/wintun.h), [signed distribution](https://www.wintun.net/).

OWL's Linux interface is actually `IFF_TAP`, and its data path reads/writes Ethernet frames. Therefore the Windows host adapter must synthesize Ethernet for outgoing Wintun IPv6 packets and strip it on decoded incoming packets. Maintain a peer IPv6-to-MAC map through OWL peer callbacks; its existing link-local mapping uses modified EUI-64 from the AWDL MAC. Preserve IPv6 multicast mapping and permit neighbor-discovery/ICMPv6 traffic. Reject invalid lengths and destinations before constructing frames. This adaptation remains untested on Windows; Windows's exact on-link/neighbor behavior must be measured with the selected Wintun interface configuration. [TAP creation](https://github.com/jedbillyb/owl/blob/832d70f815c3d4a06a02117bf0fc5e868daa1ff0/daemon/io.c#L127), [host TX framing](https://github.com/jedbillyb/owl/blob/832d70f815c3d4a06a02117bf0fc5e868daa1ff0/daemon/core.c#L133), [decoded Ethernet](https://github.com/jedbillyb/owl/blob/832d70f815c3d4a06a02117bf0fc5e868daa1ff0/src/rx.c#L369), [peer address mapping](https://github.com/jedbillyb/owl/blob/832d70f815c3d4a06a02117bf0fc5e868daa1ff0/daemon/netutils.c#L658).

Configure the AWDL-derived local IPv6 address using `InitializeUnicastIpAddressEntry`/`CreateUnicastIpAddressEntry` on the Wintun LUID; wait until DAD reports a usable address. This requires elevation. Use `ConvertInterfaceLuidToIndex` to supply the socket scope ID and multicast interface; do not persist a transient interface index. Set the virtual interface MTU through `GetIpInterfaceEntry`/`SetIpInterfaceEntry` (`NlMtu`), initially matching OWL's 1450-byte limit. Verify interface-local routes and remove only configuration created by the process. These are the required integration APIs, not actions performed during research. [Address configuration and DAD](https://learn.microsoft.com/en-us/windows/win32/api/netioapi/nf-netioapi-createunicastipaddressentry), [LUID conversion](https://learn.microsoft.com/en-us/windows/win32/api/netioapi/nf-netioapi-convertinterfaceluidtoindex), [interface fields](https://learn.microsoft.com/en-us/windows/win32/api/netioapi/ns-netioapi-mib_ipinterface_row), [interface updates](https://learn.microsoft.com/en-us/windows/win32/api/netioapi/nf-netioapi-setipinterfaceentry).

## License boundaries

OWL's protocol and daemon headers explicitly grant GPL version 3 or later. Devourer supplies GPL version 2 and labels the project GPL-2.0, without an inspected project-wide later-version grant. Do not assume this permits linking it into an OWL binary. GPLv2-only and GPLv3 combinations cannot be distributed as one program; GPLv2-or-later would permit selecting GPLv3 if every included component carried that permission. [OWL grant](https://github.com/jedbillyb/owl/blob/832d70f815c3d4a06a02117bf0fc5e868daa1ff0/src/state.c#L1), [Devourer license declaration](https://github.com/OpenIPC/devourer/blob/f369aac553c9ce884901115ef9e66509f93c5683/README.md#license), [FSF explanation](https://www.gnu.org/licenses/identify-licenses-clearly.en.html).

Separate executable names and separate license/source notices are necessary but not sufficient by themselves. Use ordinary packet bytes and generic radio controls over IPC, support independent clients, and avoid exchanging internal peer/ring structures or protocol callbacks across the boundary. FSF distinguishes ordinary process communication from communication that effectively combines programs through intimate internal semantics. Keep corresponding source/build instructions available for each modified GPL component. [FSF aggregation guidance](https://www.gnu.org/licenses/gpl-faq.en.html#MereAggregation).

Use Wintun's MIT alternative for `api/wintun.h` and the official signed DLL under its bundled redistribution license. Wintun's source and `example/example.c` are GPL2; independently implement the loader/adapter code rather than copying that example into the GPL3 OWL process. Preserve the DLL's supplied license notices. [Dual-licensed API header](https://git.zx2c4.com/wintun/tree/api/wintun.h), [example's grant](https://git.zx2c4.com/wintun/plain/example/example.c), [distribution license distinction](https://www.wintun.net/).

## Qualification required before reporting support

No committed AWDL radio PCAP was found in the inspected OWL tree, author's `airdrop-mt7921` tree, SEEMOO Wireshark-AWDL tree, or current Wireshark test capture listing. The OWL channel and TX-gate tests do contain channel sequences the author says were captured from an iPhone on 2026-07-31: idle, transfer escalation and peak occupancy. These are useful independent scheduler input fixtures, not complete captured packets. Radiotap's `check/*.bin` fixtures verify radiotap parsing only. [Captured sequence literals](https://github.com/jedbillyb/owl/blob/832d70f815c3d4a06a02117bf0fc5e868daa1ff0/tests/test_awdl_channel.cpp#L29), [TX regression scenario](https://github.com/jedbillyb/owl/blob/832d70f815c3d4a06a02117bf0fc5e868daa1ff0/tests/test_awdl_txgate.cpp#L47), [radiotap fixtures](https://github.com/radiotap/radiotap-library/tree/94984dd829a605a2d7af55241145c159607f3b30/check).

For offline frame qualification, hand-construct fixed byte fixtures and decode them with the independent Wireshark AWDL dissector rather than only feeding OWL's serializer output back into its own parser. Label them synthetic. Wireshark registers Apple AWDL's vendor action OUI and LLC PID `0x0800`, and separately decodes action TLVs and data headers. Include both action frames and IPv6 data, malformed/truncated TLVs, missing radiotap metadata, FCS variants and QoS A-MSDU. Pin the external decoder revision for repeatability. [Independent dissector at `ad85ea3cb5af4e9665f1b3e3cda5bee94b71ab73`](https://github.com/wireshark/wireshark/blob/ad85ea3cb5af4e9665f1b3e3cda5bee94b71ab73/epan/dissectors/packet-awdl.c#L1438).

Existing protocol tests and replay fixtures can verify parsing, scheduling, byte framing and failure handling without hardware. They cannot prove actual channel switching, RX, TX or iPhone interoperability. Require independent on-air evidence for action and data TX, correct FCS, receiver-visible channel transitions, measured scheduling latency, then native iPhone discovery/consent and byte-for-byte delivery in both directions. Exercise stop, worker failure, device removal and restoration of ordinary Wi-Fi ownership. The native driver, OWL adapter and Wintun interface are separate readiness checks; none should imply the others succeeded.
